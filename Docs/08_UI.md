# ONE BRAHAM — interface

The HUD, the menus and the settings. What each element is for, why it looks the
way it does, and the exact numbers.

**Interface brief in one line:** it should look like a building's signage
system — restrained, legible, slightly institutional — and it should disappear
the moment a player does not need it. Nothing in this game pulses, bounces,
rotates or sparkles.

---

## 1. Why the HUD is built in C++

`UOneBrahamHUDWidget` builds its entire layout from code when its widget tree has
no root. This is deliberate and it has three consequences that matter:

1. **The game is playable before any UMG asset exists.** A fresh clone with no
   content has a working HUD, crosshair, compass, health, ammo and extraction
   timer.
2. **The layout cannot be broken by a designer's edit.** The critical path is not
   living in an asset that can be replaced with a wrong one.
3. **A designer can take over one element at a time.** Adding a widget to
   `WBP_OneBrahamHUD` overrides that element; everything else keeps coming from
   code. This is how UI work should degrade.

`WBP_OneBrahamHUD` is the override path. `DTC_HUDStrings` holds every string the
HUD shows so it can be localised and reviewed by a writer without opening a
widget.

## 2. Palette and type

### Colour

| Name | RGB (0–1) | Where |
| --- | --- | --- |
| Primary blue | 0.000, 0.439, 0.753 | friendly UI, objective, own team |
| Deep navy | 0.016, 0.063, 0.145 | panel backgrounds (0.86 alpha) |
| Signal blue | 0.078, 0.522, 1.000 | pings, interaction prompts, extraction |
| Safety yellow | 1.000, 0.804, 0.000 | warnings, low ammo, lockdown |
| Emergency red | 0.867, 0.118, 0.122 | critical health, damage direction, purge |
| Light grey | 0.878, 0.898, 0.922 | body text |
| White | 1.000, 1.000, 1.000 | emphasis only |

These seven come from `Config/DefaultGame.ini` `[OneBrahamGameSettings]`, and
`OneBrahamUIStyle.cpp` reads them from there. `build_ui.py` verifies the two
agree on every run, so the ini and the code cannot drift.

### Type scale

| Token | Size (px at 1080p) | Weight | Use |
| --- | --- | --- | --- |
| Micro | 10 | Regular | timestamps, key hints |
| Small | 12 | Medium | labels, captions, squad list |
| Body | 14 | Regular | subtitles, descriptions |
| Medium | 18 | Medium | ammo count, objective line |
| Large | 28 | Bold | health, hold timer |
| Huge | 44 | Bold | extraction countdown |
| Title | 64 | Black | mode name on the loading screen |

Tabular figures are required for ammo, health, the timer and the scoreboard. A
number that jitters when it changes is a number a player cannot read at a glance.

### Spacing and shape

Spacing scale: 2, 4, 6, 8, 12, 18, 24, 32 px. Corner radius: panels 4 px,
buttons 2 px, pill 8 px. Panel treatment: one flat fill at navy 0.86 alpha, a
1 px light-grey 0.18 border, and no drop shadow. Anything else reads as a game
UI, and this game's UI is supposed to read as part of the building.

## 3. The in-match HUD

| Element | Where | Shows | Hides when |
| --- | --- | --- | --- |
| Crosshair | centre | dynamic gap, hit marker, spread bloom | aiming (replaced by the optic), dead |
| Health | bottom left | 100 HP + 50 armour, as one bar with an armour segment | dead |
| Ammo | bottom right | magazine / reserve, weapon name, fire mode | dead |
| Objective | top centre | the current objective line, the floor you are on | warm-up |
| Squad list | left | four names, HP bars, downs, keycards held | dead |
| Compass | top centre band | 120° field, map pings, squad markers | never |
| Extraction | top centre, below objective | the countdown during `Arriving` and `Holding` | no extraction running |
| Lockdown | top right | stage, seconds to the next stage | stage is `Normal` |
| Damage direction | screen edge, 0.9 s | an arc, sized by damage | always |
| Kill feed | top right | 7-second entries, icon + name + weapon | never |
| Interactions | centre, below the crosshair | prompt, hold progress ring | nothing in reach |
| Voice state | left, above the squad | who is transmitting, channel | nobody is talking |
| Downed overlay | full screen | bleed-out timer, revive progress, "hold to call for help" | not downed |
| Ping | world space | 6-second marker, distance | expired |
| Subtitles | bottom centre | every voice line, 2 lines maximum | disabled in settings |

### The three rules the HUD follows

1. **Nothing is always on unless it is always relevant.** The extraction timer
   appears when an extraction exists; the lockdown indicator appears when the
   building starts locking down. A HUD that shows everything is a HUD nobody
   reads.
2. **Every element is legible on a grey wall and on a black stairwell.** All text
   has a 1 px dark outline and a 40% black backing; the crosshair has a 1 px
   outline in both colours.
3. **The player's own state is never ambiguous.** Health, ammo and bleed-out are
   readable in one glance from the corner of an eye, at 1080p, on a TV at 3 m,
   and with the HUD at 80% scale (a settings option that exists because some
   players need it).

## 4. Menus

| Screen | Contents |
| --- | --- |
| Main menu | PLAY (modes), WARDROBE, SETTINGS, SERVER BROWSER, QUIT. Steam overlay aware. The backdrop is a slow camera move down the 15th-floor corridor at dawn |
| Deploy screen | archetype carousel (six), loadout (primary, sidearm, utility ×3), squad display with ready state, spawn preview |
| Wardrobe | twelve cosmetic slots, unlocks, no stat text anywhere, and a single line at the bottom: *"Cosmetics are cosmetic. Nothing here changes how you play."* |
| Settings | video, audio, controls, gameplay, accessibility. Every setting persists to `OneBrahamSaveSettings` |
| Results | survivors, damage, objectives, progression. Squad-focused, not a leaderboard |
| Server browser | Steam server list, favourites, ping, mode filter, player count |
| Loading | map name, mode, squad, and a flat diagram of the floors climbed so far |

### The deploy screen is the most important screen

It is where a player makes three decisions in thirty seconds — who they are, what
they carry, where they go — and the design goal is that those three decisions
should each be obvious and interesting. The archetype is cosmetic; the loadout is
not; the spawn preview shows the first 20 m of the map.

### Settings that must exist

| Group | Settings |
| --- | --- |
| Video | resolution, display mode, quality preset 0–4, resolution scale, FOV 60–110, motion blur 0–100%, DOF, film grain, chromatic aberration, V-Sync, frame cap |
| Audio | master, music, ambience, SFX, weapons, footsteps, dialogue, announcements, UI, voice; a mono mix; dynamic range (night mode / cinema) |
| Controls | every action rebindable, per-device, with conflict detection; sensitivity, ADS multiplier, inverse Y, hold-or-toggle for sprint, crouch and aim |
| Gameplay | HUD scale 80–120%, crosshair style and colour, damage numbers, hit markers, subtitles with size and background, ping wheel, objective markers |
| Accessibility | subtitles on by default, colour-blind modes for the four palettes used in the game, high-contrast prompts, hold-to-press durations (0.5× / 1× / 2×), screen shake intensity 0–100%, audio visualisation for the alarm and the extraction beacon |

Colour-blind modes are not a filter slapped over the frame: the four palettes
(gameplay markers, foliage-free environments, the purge lighting, and the alarm
beacons) each have their own alternative values, because a filter that turns the
whole game orange is a filter that makes the game worse.

## 5. CommonUI

CommonUI is used for the menu stack (activation stacks, back handling, input
routing), because a PC game with a controller needs focus management that works
and rolling that yourself is three weeks for a worse result. The in-match HUD
does not use CommonUI at all: it is a single always-on widget and the extra
layer of routing would cost frame time for nothing.

## 6. Building the UI content

```
Scripts\BuildContent.bat --only ui
```

creates 10 widgets, the HUD string table (31 strings) and the font slot, and
verifies the palette. The font is imported by `Scripts\Import_Font.bat`; the
composite font's weights and sizes are the table in section 2.
